# 踩坑清单（各期实际遇到）

## 运维 / 远程
- 渲染机 默认 shell 是 cmd：串联用 `&`；`for` 循环经 ssh 容易坏 → 写 Python 驱动脚本。
- GBK 输出乱码：`chcp 65001`、`PYTHONIOENCODING=utf-8`；读 json 显式 `encoding="utf-8"`。
- 隐藏启动：`launch.ps1`（Win32_Process Create）+ 完整路径；绝不 schtasks /it、不开可见窗口。
- 等待循环别信旧日志：日志用 `>` 覆盖、完成标记每轮新写；先确认进程（`tasklist | findstr ffmpeg python`）。
- Wikimedia 429 / Pixabay 403 / incompetech 不通 → 沙盒（有代理）下载再 scp。
- 脚本名别用 `select.py`；py3.11 f-string 内不能有反斜杠。

## Seedance / Ark
- 输入 dict 里的 `#` 注释吞键 → 总是 5 s。
- `.env` 的 `ARK_SEEDANCE_MODEL` 会覆盖 variant → 显式传 model。
- 首帧模式要 `aspect_ratio` adaptive；seedance_ark.py 设置参考音频时 `duration` 变量被遮蔽（本地已修，上游 bug）。
- 片长 > 台词需要 → 重复说词填时间；时长 `ceil(1.15·tts+1)` + "说完就闭嘴"，干净率 ~50% → ~85%。
- Seedance 读音偏差：塞尔南→"林"、诸葛亮偶尔"朱可亮"；用 PRON 提示、改写，或多拍几条挑。
- 链式 4–5 跳后漂移、越推越近；从 plate 重新起链。
- 含人脸参考的 Seedream 图被拦；国旗特写被拦。
- 工具返回的 cost 是 USD。

## 口型 / 同步
- LatentSync 会保留底片原有嘴动，底片需是静音 plate；3/4 侧脸弱；用户嫌机器感 → 不用。
- 声画漂移（到 −3 s）：段音频 `apad` + `-t` 对齐视频；混音 `aresample=48000:async=1:first_pts=0`；用 probe 的实际段长排时间线。
- `ONLY=` 复用旧段会把旧方案（口型段）混进成片 → 主持人段永远重建；切换方案后把旧段移走并检查 concat.txt。

## 音频
- loudnorm 输出 192 kHz → 后接 `aresample=48000`。
- 静音原片 + 床底音乐被混没 → 音乐放进该段自身音轨。
- 停顿收紧阈值过松会剪掉轻声字（"也"）；过严（词尾保护覆盖所有词）会让重复字剪切失效 → 重复字剪切不受保护约束，保护只对"确有声音"的词尾生效。
- take 恰好在最后一个字结束（"呀"）时 0.2 s 淡出会吞字 → 淡出缩到 0.06 s。
- whisper 用 initial_prompt 会丢开头；whisper 会把停顿算进拉长的词里（"的人[2.10-3.64]"）→ 停顿检测用声学能量，不只靠词时间戳。

## 画面
- zoompan 推拉静态图会抖（且用户不要静态图）。
- 60/30 fps → 25 fps 丢帧显得抖 → framerate 混帧；vidstab 让运动镜头更糟。
- 网络视频的台标/烧录字幕：cropdetect + 内缩；片头演职员表镜头要换掉。
- 封面用 `-loop 1` 图像输入参与 concat 会卡死 → 做成普通 2.5 s 首段。
- 结尾卡窗口不能被时间窗 clamp，否则从错误帧开始。

## 主持人镜头内静默发呆（EP03 v5→v6，11-12）
- 症状：用户说"小柚 与君重逢 说的是…就卡住了"。不是剪切/拼接，而是 Seedance 单条内部问号/句号后 1–2 s 无声 + 几乎不动（225 甚至整帧冻结）。v5 时我把 1.3–1.5 s 当"自然句末停顿"放过——错，镜头内 > ~0.8 s 就像卡。
- 修法：`ramp_plan()` 快放静默中段（保留前后各 0.15 s 原速），目标 0.55 s；倍速上限 4×，再受动作限制（p95 说话动作、累计跳帧变化 ≤ 说话最大单帧变化）。验证：`rampcheck.py`（段落 p95/max 运动 ≤ 原条，ASR 全句完整）。
- 不要用剪切代替快放：剪切 = 头嘴瞬移；快放 = 连续，只是静默段稍快。
- 说完后继续"演"（叹气、摇头）且无声的，用 `END_AT` 截掉。
- 24 fps 素材进 25 fps 成片：整条 25/24 提速，不要 `fps=25` 补帧（每秒一顿）。

## EP05 Seedance 2.0 降本（11-13，用户余额 500，目标 ~200 元，主持人全部出镜）
- 价格（官方刊例，720p ≈ 21.6k token/s；480p 16:9 864×496 ≈ 10k token/s）：2.5 ≈ 1.56 元/s；2.0 标准 ≈ 1.0；**2.0 fast ≈ 0.8（720p）/ 0.37（480p）**；2.0 mini ≈ 0.5（720p）。资源包按刊例价预付、无视频输入时按 ~1.68 倍抵扣 → 不省钱。
- **用户选定：2.0 fast 480p**，成片里放大到 1080p（lanczos + 轻微 unsharp），中近景主持人看着没问题；脸比 fast 720p 更贴定妆照。
- 2.0 单条 ≤15 s、参考音频 2–15 s：台词超长在剧本里拆成两个镜头（`shot(..., sub="b")` 不改后续 id），前后两段同链生成（后半段用前半段末帧），后半段换机位、"紧接上一句、开头不停顿"——用户要求"两段的衔接要做好"。
- **"烫嘴"**（mini 首测，用户："说话烫嘴一样，没短句"）：原因 = 参考音频用了收紧停顿的 `voice()` + 提示词"紧凑/只停半秒" + 时长给得紧 + 说话时安排了低头摇头动作。修法：老渡参考音频用**未收紧、speech_rate -15** 的 TTS；提示词"语速节奏停顿完全以音频1为准，逗号换气、句号稍停、吐字清晰；说话时头部稳定"；时长 `ceil(1.12×tts+1)`。网上实测也说 2.0 台词一多就"机械快嘴"，建议参考音频放慢到 ~80%。
- mini 720p 脸稳但吐字含糊/吞字；fast 吐字清楚，720p 时脸会走样（偏瘦）。
- 两个 studio_produce 进程并行跑同一 plan 会抢同一个 take 号（json 只在结束时写）→ 不同 variant 对比要串行，或分开 plan id。
- 丢了本地 take 可从 Ark 任务列表找回：`recover_task.py <model子串> <out.mp4>`（GET /contents/generations/tasks，video_url 有效期内）。文件操作先确认复制成功再删除（11-13 误删过一次）。
- **漏字（11-13 用户审片抓到：116「九岁那台」漏"那"、116b「离倒闭只有三十天」漏"只"）**：旧 QC 把"漏 1 个字"当容忍（stutterscan 要 ≥2 个音节才报 MISS，choose 只看 REP/SIM），Whisper 整句识别还会按通顺"脑补"。修法 = `strict_check.py`：Whisper `word_timestamps=True, condition_on_previous_text=False` 逐字识别，按拼音（多音字任一读音相同即算同音：着/著、地/的）比对，**任何漏字/多字/异音字 = 不合格**；开头没识别到的部分单独 `clip_timestamps` 再听。choose 把 strict 失败的 take 当 reject。用它扫出了 070 漏"就"、057 多"是"。仍分不出的同音重复（将降/将将）交给人耳。
- **审片方式（用户要求）**：不要只给成片；把选用的生成原片按顺序拼成一条，左上角标 `No.序号 镜头号 说话人 (take)`、下方标台词（`reel.py [ids] [out]`），用户报序号，补拍后只给补拍那几条的小审片。
- 停顿快放：EP05 2.0 fast 的长停顿被 2–4× 快放，用户觉得"卡顿" → `RAMP_CAP=1.6, RAMP_MAX=0.7`；宁可自然停顿，也不要加速感。
- Paraformer（FunASR）二审需要在 渲染机 装 torch+funasr：auto 模式下被权限拦截（外部代码），要用户显式授权。

## EP06 正片v2 → v3（11-18，用户："还是有卡顿和重复说词，小柚突然闪到屏幕前面"）
- **整条 ASR 会把重复字"顺掉"**：strict_check 对整条 take 识别，「熄着着」「晚晚一步」都听成了正确台词。新增 `takecheck.py`（按停顿切块、每块单独识别、拼音比对，insert 即拒）+ 成片版 `deepscan.py host|vo`。交付前必须跑 deepscan。
- **Seedance 会在一条视频里自己切镜头**（143/145：从座位切到大特写 = "闪到屏幕前面"）。takecheck 的帧差 spike 检测 + 提示词【SHOT】加"一镜到底：中途绝不切镜头、不跳剪、不突然推近或换景别"。重拍里 145_t2 仍然切了——每条 take 都要看帧条（takestrip.py）。
- **CONFORM×RAMP 的 bug（真正的卡顿来源）**：每段视频 `setpts/(sp*k)` 而音频段只按 sp 截取 → 每段视频比音频短 4%，concat 用重复帧补齐 → 每个快放点画面冻结 0.2–0.3 s。修复：各段只 `/sp`，concat 后整体 `setpts=PTS/k`；段边界对齐 24 fps 帧格；cd 取视频流时长。用 `segtest.py`（RAMP/CONFORM 组合 × 冻结帧检测）验证。
- **停顿快放被单个动作否决**：停顿里一次眨眼/甩头触发 spike guard，整段不快放 → 老渡句间停顿 1.3–1.7 s。改为按大动作把停顿切开，只快放平静的部分，上限 2.0×（仍受说话动作幅度限制）。"相似帧拼接"不可行：Seedance 停顿里一直在动，最像的两帧也有 2–3 倍正常帧差。
- 老渡参考音频不收紧时句间停顿太长；收紧到 0.6 s 又"烫嘴"（EP05）→ 折中 `maxpause 0.85`（studio_plan `LD_TIGHT`）。
- 小柚表演写"叹了一口气"会在台词前多出"哼"声：开口前不要安排出声的动作。
- 从沙盒写的 .cmd 含中文时必须 CRLF（LF 时 cmd 报"系统找不到指定的路径"，什么都没跑）。

## EP06 正片v4（11-18，用户："人物部分卡顿，声音开大有爆破声，一直处理得不好"）
- **真凶：成片混音里的 `aresample=async=1`**。joined.mkv（concat -c copy）每段音视频长度差累积，async 漂移超过 0.1 s 就"硬补偿"——在词中间插入 ~0.12 s 静音，两侧各一个咔哒 = 卡顿 + 爆破声。ASR 和画面检查都看不出来，只有**频谱对比**（specat.py：片段 / 人声轨 / 成片同一时刻）能看到。
- 修复：人声轨在 numpy 里逐段解码、按各段容器时长补齐/截断后首尾相接（voice.wav，f32），混音不再用 async；`voicecmp.py voice.wav 成片` 每 10 ms 比对，成片比人声轨低 12 dB 以上即为断音——交付前必须为 0。
- 主持人音频：Seedance 原声峰值接近满幅，单遍动态 loudnorm 会抽吸、过冲 → 改为 highpass 70 Hz + 按 take 实测响度的固定增益 + alimiter(-3 dBFS)；成片：固定增益到 -16 LUFS + alimiter(-1.5 dBFS)，不用动态 loudnorm。
- 测峰值别用 `-ac 1`：ffmpeg 立体声下混是 0.707·(L+R)，L=R 时虚高 3 dB（误报削顶）。用 `pan=mono|c0=c0` 或 astats。
- 新工具：audiocheck.py（原片/片段/成片三级：咔哒、低频噗声、断音、音画偏移 ms）、specat.py、holescan.py、voicecmp.py。

- 壁炉火苗 / 窗外飘雪让 ramp 的动作否决全部生效 → 停顿 1–2 s 没被压（用户会听成卡顿）：动作只量人物区域；静音检测先做 200–4000 Hz 带通（720p 带底噪/火声）。
- 余额 0 时 Seedance、Seedream 都能调用 → 调用成功不代表走了资源包，要用户在控制台核对。
